# Compare Pages — 1v1 Pipeline Integration (Phase 3)

This document describes how to wire the existing **8 per-competitor page types** from `page_content` into the Sliq Pay marketing site after multi-provider compare pages are live.

## Current state (Phase 1)

| Route | Source | Template |
|-------|--------|----------|
| `/compare` | Redirect | → default slug |
| `/compare/[slug]` | `src/content/compare/pages/{slug}.json` | `ComparePageTemplate` (8-section marketing UI) |

Multi-provider pages are generated by `agents/comparePageBuilder.ts` and exported via `npm run export:compare`.

## Phase 3 target

| Route | Source | Template |
|-------|--------|----------|
| `/compare/vs/[competitor]/[pageType]` | `page_content` table (1v1) | `CompareOneToOneTemplate` (new) |

Use a `/compare/vs/` prefix to avoid colliding with multi-provider slugs like `remitly-vs-wise-vs-sliq-pay`.

### Page types (from `agents/pageTypes.ts`)

- `sliqpay-vs-competitor`
- `which-is-cheaper`
- `which-is-faster`
- `which-is-safer`
- `which-is-more-convenient`
- `which-is-better-for-tourists-visiting-india`
- `which-is-better-for-nris`
- `competitor-alternative-sliqpay`

Each type has a different JSON shape (see `prompts/summarizer/*.txt`). Do **not** map these into the 8-section `ComparePageTemplate`.

## Recommended export flow

1. Add `scripts/exportCompareOneToOne.ts` in this repo.
2. Query:

```sql
SELECT c.slug AS competitor_slug, pc.page_type, pc.content, pc.meta_title, pc.meta_description
FROM page_content pc
JOIN competitors c ON c.id = pc.competitor_id
WHERE pc.page_type = ANY($1::text[])
```

3. Write to Sliq-website:

```
src/content/compare/vs/{competitor}/{pageType}.json
src/content/compare/vs-index.json   # published paths for generateStaticParams + sitemap
```

4. Add `npm run export:compare-one-to-one` and a website alias `import:compare-one-to-one`.

## Website implementation checklist

- [ ] `src/lib/compare/oneToOneData.js` — load vs-index + per-page JSON
- [ ] `src/app/compare/vs/[competitor]/[pageType]/page.js` — `generateStaticParams`, metadata, notFound
- [ ] `CompareOneToOneTemplate.jsx` — section mapping per `pageType` (start with `sliqpay-vs-competitor`, `which-is-cheaper`)
- [ ] Extend `next-sitemap.config.js` with vs-index paths
- [ ] Design sign-off for which pipeline JSON fields map to which UI blocks per page type

## Operational commands (future)

```bash
# Pipeline repo — refresh 1v1 content for one competitor
npm run pipeline -- --ids 1 --summarize-only

# Export to marketing site
npm run export:compare-one-to-one

# Website repo — pull exports (optional alias)
npm run import:compare-one-to-one
```

## Why separate templates?

Multi-provider pages are table-heavy marketing comparisons (Wise + Remitly + Sliq). The 1v1 pipeline pages are narrative SEO landers (hero, verdict banner, fee breakdown, scenarios, FAQ). Merging both into one template would force awkward JSON adapters and block independent design iteration.
